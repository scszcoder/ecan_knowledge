# ecan_knowledge — cloud listing agent

A serverless AWS service that turns vague product input (a few phone photos, some notes) into a marketplace listing.
Local agents reach it through an MCP tool and get **streamed progress** while the job runs.

```
local agent ──MCP stdio──> shim/ecan_listing_mcp.py ──GraphQL──> AppSync ──> api λ ──> Step Functions
                              │  photos: pre-signed PUT ──> S3                         │ step λs
                              └──<── WebSocket /jobs/{jobId} ── AppSync Events <── emit (DynamoDB first, then publish)
```

Status: **scaffold**.  API, workflow, streaming and the MCP shim work end to end; the workflow steps are stubs that
emit realistic events with placeholder data.  See [docs/DESIGN.md](docs/DESIGN.md) for the design and the build order.

## Layout

| path | what |
|---|---|
| `api/schema.graphql` | GraphQL API: `createUploadUrls`, `startListing`, `answer`, `listing`, `events` |
| `functions/api.py` | AppSync Lambda resolver for every field |
| `functions/steps.py` | workflow steps (stubs): intake → 3 identify lanes → verify → ask seller? → draft → validate → images |
| `functions/common.py` | job state and `emit()`: write the event to DynamoDB, then publish to `/jobs/{jobId}` |
| `infra/stack.py` | CDK stack: S3, DynamoDB, AppSync GraphQL + Events, Step Functions, Lambdas |
| `shim/ecan_listing_mcp.py` | local MCP server: uploads photos, follows the stream, reports MCP progress |
| `tests/test_local.py` | end-to-end test without AWS (fake cloud + local WebSocket server) |

## Setup

```powershell
python -m venv .venv; .venv\Scripts\activate
pip install -r requirements.txt
python -m unittest tests/test_local.py          # no AWS needed
```

## Deploy

Needs AWS credentials and the CDK CLI (`npm i -g aws-cdk`).

```powershell
cdk bootstrap        # once per account/region
cdk deploy           # prints GraphqlUrl, GraphqlApiKey, EventsHttpDns, EventsRealtimeDns, EventsApiKey
```

Tables and the bucket are `RETAIN`ed on `cdk destroy`; delete them by hand when tearing down a dev stack.

## Use from a local agent

```powershell
claude mcp add ecan-listing `
  -e ECAN_GRAPHQL_URL=<GraphqlUrl> -e ECAN_GRAPHQL_KEY=<GraphqlApiKey> `
  -e ECAN_EVENTS_HTTP=<EventsHttpDns> -e ECAN_EVENTS_REALTIME=<EventsRealtimeDns> -e ECAN_EVENTS_KEY=<EventsApiKey> `
  -- C:\path\to\ecan_knowledge\.venv\Scripts\python.exe C:\path\to\ecan_knowledge\shim\ecan_listing_mcp.py
```

Tools:

- `start_listing(image_paths, notes?, marketplace?, target_price?)` — uploads the photos, starts the job, streams
  progress, and returns the draft, or `status: needs_input` with questions.
- `answer(job_id, answers)` — answers the questions and follows the job to the next stop.
- `get_listing(job_id)` — current state; waits for the next stop if the job is still running.

A tool call follows the stream for up to `ECAN_WAIT_SECONDS` (default 600) and then returns `status: running`.

## Event stream

Every step emits events on channel `/jobs/{jobId}`:

```json
{"jobId": "…", "seq": 14, "ts": "…", "stage": "identify", "type": "candidate", "data": {"lane": "web_image", "…": "…"}}
```

Types: `stage`, `found`, `candidate`, `match`, `question`, `draft_delta`, `image`, `done`, `error`.
Events are written to DynamoDB before they are published.  A client subscribes first, then starts the job (the jobId
is generated by the client), and fills any gap in `seq` (late subscribe, reconnect, lost publish) with the `events` query.
